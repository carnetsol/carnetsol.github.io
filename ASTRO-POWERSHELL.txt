DÉVELOPPEMENT
═════════════

Compilation locale (statique) : npm run build
    → crée dist/ avec tout le site en HTML/CSS/JS
    → prend 4-10 secondes selon le nombre de notules

Serveur de développement : npm run dev
    → écoute sur http://localhost:4321 (recharge auto à chaque changement)
    → arrêt : Ctrl+C

Aperçu du site compilé : npm run preview
    → lance le contenu de dist/ pour vérifier avant publication


ARCHITECTURE DES FICHIERS MODIFIÉS
═══════════════════════════════════

Notules archives (JSON) :
    src/content/notules/2000.json, 2001.json, … (~3 300 fichiers)
    → générées par la migration Dotclear, ne pas éditer à la main
    → remplacées à chaque nouvelle migration

Notules récentes (Markdown) :
    src/content/nouvelles/*.md
    → écrivez-les directement ici
    → format : en-tête YAML (titre, date, categories, chapo) + contenu

Correctifs (JSON, optionnel) :
    src/content/corrections/2030.json
    → appliqués lors du rendu, survivent aux migrations
    → peuvent remplacer un champ entier ou faire des find/replace

Catégories (JSON unique) :
    src/content/categories.json
    → liste des rubriques, slug, ordre, description

Pages web :
    src/pages/*.astro
    src/pages/css/*.astro
    src/pages/archives/index.astro
    src/pages/categorie/*.astro
    etc.

Styles CSS :
    src/styles/global.css
    → charte Keepsake (or, parchemin, Georgia/Lucida)
    → y compris la césure et les voisines

Composants réutilisables :
    src/components/*.astro
    → NotuleCard.astro (affichage d'une notule)
    → BoiteRecherche.astro (formulaire de recherche)
    → Pagination.astro (fil à 50 notules + pagination)


AJOUT D'UNE NOTULE RÉCENTE
══════════════════════════

1. Créer src/content/nouvelles/mon-titre.md

    ---
    titre: "Mon titre"
    date: 2026-08-28
    categories: ["Intendance"]
    chapo: "Chapô court pour le fil."
    ---

    Texte de la notule en Markdown.
    
    Paragraphes, **gras**, *italique*, [lien](url), images, etc.

2. npm run build

3. Vérifier dans dist/css/2026/08/28/mon-titre/index.html

4. Si c'est bon : git add src/content/nouvelles/mon-titre.md


MODIFICATION D'UNE NOTULE D'ARCHIVE
═══════════════════════════════════

NE PAS éditer src/content/notules/*.json directement (régénération à chaque
migration). Créer un correctif à la place :

1. Créer src/content/corrections/POSTID.json (POSTID = numero de la notule)

    {
      "postId": 2030,
      "note": "Correctif appliqué le 28/08/2026",
      "titre": "Titre corrigé",
      "remplacements": [
        {
          "chercher": "vieux texte",
          "remplacer": "nouveau texte",
          "regex": false
        }
      ]
    }

2. npm run build

3. git add src/content/corrections/POSTID.json

VÉRIFICATIONS AVANT PUBLICATION
════════════════════════════════

npm run build
    Si ✓ Completed : c'est bon, vous pouvez pousser.
    Si [ERROR] : arrêtez, corrigez, recompiilez.

git status
    Montre les fichiers modifiés et non validés.

git diff src/content/nouvelles/mon-titre.md
    Affiche ce qui a changé en détail (utile avant de valider).

git log --oneline -5
    Affiche les 5 derniers commits locaux (pour vérifier qu'on est à jour).


GIT — FLUX DE TRAVAIL
═════════════════════

Vérifier où vous êtes :
    git branch
    git status
    → Vous devez être sur 'main' ou 'master' et aucun changement en cours

Récupérer les modifs publiées par ailleurs :
    git pull

Préparer un commit :
    git add src/content/nouvelles/mon-titre.md
    git add src/content/corrections/2030.json
    git add src/styles/global.css

Ou tout d'un coup (attention : ajoute tout ce qui a changé) :
    git add -A

Validez vos changements localement :
    git commit -m "Nouvelle notule : Mon titre"
    git commit -m "Correctif notule 2030"
    git commit -m "Césure et voisines dans le CSS"

Puis publiez sur GitHub :
    git push

Voir votre travail en ligne (quelques secondes) :
    https://carnetsol.netlify.app
    Netlify compile et publie à chaque push.


GESTION DE L'HISTORIQUE
═══════════════════════

Voir ce qu'on a fait :
    git log --oneline
    git log --oneline -10   (les 10 derniers)
    git log --oneline --graph

Annuler le dernier commit (pas encore poussé) :
    git reset --soft HEAD~1
    (Les changements restent dans git add, le commit est défait.)

Abandonner complètement une branche de travail :
    git reset --hard HEAD
    (Revient à l'état du commit précédent ; DESTRUCTIF.)

Voir les différences :
    git diff
    (Comparer la version locale avec le dernier commit.)

    git diff HEAD~1
    (Comparer avec l'avant-dernier commit.)


PAGINATION ET NOTULES
═════════════════════

Le fil affiche 50 notules par page.

Pages générées automatiquement :
    /css/                    → page 1 (50 premières)
    /css/page/2/             → page 2 (50 suivantes)
    /css/page/3/             → etc.

Navigation :
    Liens « 50 précédentes / 50 suivantes »
    Bouton « Charger les 50 suivantes » (JavaScript)
    → pas de rechargement de page, contenu recopié en bas


VOISINES (navigation entre notules)
═══════════════════════════════════

Chaque notule affiche le lien vers la précédente et la suivante en bas.

Ordre : par date décroissante (plus récente d'abord).

Archives et notules récentes : fusionnées dans le même ordre chronologique.

Pas de voisines sur :
    - les pages d'alias/redirection (pages sans slug ou with partial slug)
    - les pages créées avant la modification


ARCHIVES
════════

Liste complète par année, puis mois (tous les mois affichés à la fois).

Index d'années cliquable en haut.

Lien « haut » par année pour remonter vite.

Pas de chargement dynamique : tout le HTML d'un coup (~55-60 Ko pour 3 300
notules sur 20 ans).


RECHERCHE
═════════

Page : /css/recherche/

Moteur : Pagefind (client-side, pas de serveur).

Index : construit à la compilation (npm run build).

Cherche dans : titre, chapô, corps, catégories.

Résultats : affichage immédiat dans la page, sans rechargement.

PERFORMANCE
═════════════

Compilation moyenne : 4-10 sec (dépend du nombre de notules).

Poids du site statique : ~630 MB (JS/CSS minifiés), ~50 Mo le reste compressé.

Poids d'une page notule : ~40-60 Ko (HTML+CSS+JS).

Archives : content-visibility:auto pour éviter de rendre ce qu'on ne voit pas.


TROUBLESHOOTING
═════════════════

Erreur de compilation : [ERROR] [...] Failed to call getStaticPaths
    → Vérifier qu'une constante n'est pas utilisée hors de getStaticPaths
    → Les constantes du frontmatter ne remontent pas jusqu'à getStaticPaths

Liaison qui ne marche pas :
    → Vérifier le slug : pas d'accents, pas de ponctuation, tirets seulement
    → Vérifier le chemin : /css/AAAA/MM/JJ/slug/ avec slash final

Git refuse de commiter :
    → git config user.email "vos@mails.com"
    → git config user.name "Votre Nom"

Netlify ne déploie pas après le push :
    → Attendre quelques secondes et recharger la page
    → Vérifier que le dernier commit est bien passé : git log --oneline -1
    → Consulter https://app.netlify.com (onglet "Deploys")

CHANGER AGENDA

C'est dans src/layouts/Base.astro, dans le tableau rubriques. Cherchez le commentaire qui l'accompagne :

js
// À CONFIRMER : « Agenda » pointe faute de mieux sur la saison en
// cours. Dites-moi la bonne adresse et je la corrige.
{ href: '/categorie/Saison-2026-2027/', label: 'Agenda' },

C'est la ligne href qu'il faut changer. Deux cas typiques :

Vers une notule précise (comme l'agenda de rentrée) : href: '/css/2026/08/16/3457-l-agenda-de-francilie-2026-2027-rentree-de-septembre/'
Vers un chapitre : href: '/categorie/<slug-du-chapitre>/'

Chaque nouvelle saison, c'est cette seule ligne à modifier.
